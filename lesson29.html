What Are Collections?

The Java Collections Framework provides ready-made classes and interfaces for storing and manipulating groups of objects.

Collections are commonly used with OOP because they can store objects created from your own classes.

Why Use Collections?

  • Store multiple objects
  • Search and sort data
  • Add and remove objects easily
  • Reduce manual array management
  • Build flexible applications

Collection Hierarchy

Some of the most commonly used collection types are:

Type Purpose
List Ordered collection that allows duplicates
Set Collection that does not allow duplicate elements
Map Stores key-value pairs
Queue Stores elements for processing in an ordered way

ArrayList

ArrayList is one of the most commonly used List implementations. 

import java.util.ArrayList;

ArrayList<String> names =
        new ArrayList<>();

names.add("Keerthana");
names.add("Amirtha");
names.add("Harshitha");

System.out.println(names);
[Keerthana, Amirtha, Harshitha]

Common List Methods

  • add() — adds an element
  • get() — gets an element
  • set() — updates an element
  • remove() — removes an element
  • size() — returns the number of elements
  • contains() — checks for an element

Working with Objects

Collections become especially useful when storing objects created from your own classes. 

class Student {

    String name;
    int mark;

    Student(String name, int mark) {
        this.name = name;
        this.mark = mark;
    }
}

Store Student Objects in a List

ArrayList<Student> students =
        new ArrayList<>();

students.add(
        new Student("Keerthana", 85)
);

students.add(
        new Student("Amirtha", 90)
);

for (Student student : students) {
    System.out.println(
        student.name + " - " + student.mark
    );
}
Keerthana - 85
Amirtha - 90

HashSet

HashSet stores unique elements and automatically prevents duplicate values. 

HashSet<String> names =
        new HashSet<>();

names.add("Java");
names.add("Python");
names.add("Java");

System.out.println(names);

HashMap

HashMap stores data as key-value pairs. 

HashMap<Integer, String> students =
        new HashMap<>();

students.put(101, "Keerthana");
students.put(102, "Amirtha");

System.out.println(students.get(101));
Keerthana

Map with Objects

A Map can also store objects as values. 

HashMap<Integer, Student> students =
        new HashMap<>();

students.put(
    101,
    new Student("Keerthana", 85)
);

Student student = students.get(101);

System.out.println(student.name);

Iterator

Iterator can be used to safely traverse collection elements. 

Iterator<String> it =
        names.iterator();

while (it.hasNext()) {
    System.out.println(it.next());
}

Enhanced for Loop

The enhanced for loop is a simple way to process objects stored in a collection. 

for (Student s : students) {
    System.out.println(s.name);
}

Sorting Objects

Objects can be sorted using Comparator. 

students.sort(
    (a, b) ->
        Integer.compare(b.mark, a.mark)
);
This example sorts students based on marks in descending order.

List vs Set

Feature List Set
Order Maintained Usually not guaranteed
Duplicates Allowed Not allowed
Example ArrayList HashSet

List vs Map

Feature List Map
Storage Elements Key-Value pairs
Access Index Key
Example ArrayList HashMap

OOP + Collections Example

A simple employee management example demonstrates how OOP and collections work together. 

class Employee {

    private String name;
    private double salary;

    Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    String getName() {
        return name;
    }

    double getSalary() {
        return salary;
    }
}

ArrayList<Employee> employees =
        new ArrayList<>();

employees.add(
    new Employee("Keerthana", 35000)
);

employees.add(
    new Employee("Amirtha", 40000)
);

for (Employee e : employees) {
    System.out.println(
        e.getName() + " - " +
        e.getSalary()
    );
}
Keerthana - 35000.0
Amirtha - 40000.0

Generics + Collections

Collections use generics extensively to provide compile-time type safety. 

List<Student> students =
        new ArrayList<>();
This means the list can contain Student objects only.

Choosing a Collection

  • Use ArrayList for ordered data.
  • Use HashSet for unique data.
  • Use HashMap for key-value data.
  • Use Queue when processing items in order.

Important Points

  • Collections store groups of objects.
  • Generics provide type safety.
  • List allows duplicate elements.
  • Set prevents duplicate elements.
  • Map stores key-value pairs.
  • Collections can store custom class objects.
  • OOP and collections are commonly used together in real applications.
