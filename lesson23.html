Custom Exceptions

Learn how to create your own exception classes in Java for handling application-specific errors clearly and professionally.

What is a Custom Exception?

Java provides many built-in exceptions such as ArithmeticException, NullPointerException, and ArrayIndexOutOfBoundsException.

Sometimes an application needs an error type that represents a specific business rule. In that case, we can create our own exception class.

Example: A banking application could create InsufficientBalanceException when a user tries to withdraw more money than the available balance.

Why Create Custom Exceptions?

  • Represent application-specific errors.
  • Make error messages more meaningful.
  • Improve code readability.
  • Separate business rules from normal logic.
  • Make large applications easier to maintain.

Basic Structure

A custom checked exception can be created by extending the Exception class. 

class MyException
    extends Exception {

    public MyException(
        String message
    ) {
        super(message);
    }
}

Creating a Simple Custom Exception

Let's create an exception called InvalidAgeException. 

class InvalidAgeException
    extends Exception {

    public InvalidAgeException(
        String message
    ) {
        super(message);
    }
}

The constructor passes the error message to the parent Exception class using super().

Using the Custom Exception

class InvalidAgeException
    extends Exception {

    public InvalidAgeException(
        String message
    ) {
        super(message);
    }
}

public class Main {

    static void checkAge(
        int age
    ) throws InvalidAgeException {

        if (age < 18) {

            throw new InvalidAgeException(
                "Age must be 18 or above"
            );
        }

        System.out.println(
            "You are eligible"
        );
    }

    public static void main(
        String[] args
    ) {

        try {
            checkAge(16);
        }
        catch (InvalidAgeException e) {
            System.out.println(e.getMessage());
        }
    }
}
Age must be 18 or above

Custom Unchecked Exception

A custom exception can also extend RuntimeException. 

class InvalidAmountException
    extends RuntimeException {

    public InvalidAmountException(
        String message
    ) {
        super(message);
    }
}
Remember: Extending Exception creates a checked exception, while extending RuntimeException creates an unchecked exception.

Checked vs Unchecked Custom Exceptions

Checked Unchecked
Extends Exception Extends RuntimeException
Compiler requires handling or declaration Compiler does not require handling
Useful for recoverable conditions Useful for programming or validation errors

Real-World Example: Banking

Let's create an InsufficientBalanceException. 

class InsufficientBalanceException
    extends Exception {

    public InsufficientBalanceException(
        String message
    ) {
        super(message);
    }
}

class BankAccount {

    private double balance = 5000;

    public void withdraw(
        double amount
    ) throws InsufficientBalanceException {

        if (amount > balance) {

            throw new
                InsufficientBalanceException(
                    "Insufficient balance"
                );
        }

        balance -= amount;

        System.out.println(
            "Withdrawal successful"
        );
    }
}

Handling the Banking Exception

public class Main {

    public static void main(
        String[] args
    ) {

        BankAccount account =
            new BankAccount();

        try {

            account.withdraw(7000);

        }
        catch (
            InsufficientBalanceException e
        ) {

            System.out.println(e.getMessage());
        }
    }
}
Insufficient balance

Exception Constructor

A custom exception can have a constructor that accepts a message. 

public MyException(
    String message
) {

    super(message);
}

This allows the calling code to provide a useful description of the error.

Multiple Constructors

A custom exception can have multiple constructors, just like any other Java class. 

class MyException
    extends Exception {

    public MyException() {
        super();
    }

    public MyException(
        String message
    ) {
        super(message);
    }
}

Best Practices

  • Give custom exceptions meaningful names.
  • End exception class names with Exception.
  • Provide useful error messages.
  • Use checked exceptions when callers should handle the condition.
  • Use unchecked exceptions for programming or validation errors when appropriate.
  • Do not create custom exceptions for every small error.

Lesson Summary

Custom exceptions allow developers to create meaningful error types for specific application requirements.

  • Extend Exception for checked exceptions.
  • Extend RuntimeException for unchecked exceptions.
  • Use throw to create and throw an exception.
  • Use throws to declare an exception.
  • Custom exceptions make business rules clearer.
