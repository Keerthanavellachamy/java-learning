What is a Package?

A package is a group of related Java classes, interfaces, and other components.

Packages help developers organize large Java projects into smaller and easier-to-manage sections.

Simple idea: Think of a package like a folder on your computer. Related Java files can be placed inside the same package.

Why Use Packages?

  • Organize related classes.
  • Avoid naming conflicts.
  • Control access to classes and members.
  • Make large projects easier to maintain.
  • Reuse code across applications.

Package Syntax

The package statement is normally written at the beginning of a Java source file. 

package com.jav alearn.models;

public class Student {

    public void display() {
        System.out.println("Student class");
    }
}

Correct Package Name

Package names are commonly written in lowercase letters. A reverse-domain style is often used in professional projects. 

package com.jav alearn.models;
Note: In the example above, remove the space if copying: com.jav alearn.models should be com.jav alearn.models only if that is the package name you created. For a simple project, names such as com.jav aLearn.models are best avoided.

Creating a Simple Package

Suppose we create a package called students. 

package students;

public class Student {

    public void display() {
        System.out.println("Student details");
    }
}

Package Folder Structure

The package structure can be represented like this:

javaproject/ │ ├── students/ │ └── Student.java │ └── Main.java

The folder name and package name should correspond when using the standard Java project structure.

Importing a Package Class

To use a public class from another package, Java provides the import statement. 

import students.Student;

public class Main {

    public static void main(String[] args) {

        Student student =
            new Student();

        student.display();
    }
}

Importing All Classes

You can import all accessible classes from a package using the wildcard symbol *. 

import students.*;

public class Main {

    public static void main(String[] args) {

        Student student =
            new Student();

        student.display();
    }
}
Tip: Importing a specific class is often clearer because it shows exactly which class your program uses.

Built-in Java Packages

Java provides many ready-made packages containing useful classes and interfaces.

Package Purpose Example
java.lang Core Java classes String, Math, Object
java.util Utility and collection classes ArrayList, Scanner
java.io Input and output File, FileReader
java.time Date and time API LocalDate

java.lang Package

The java.lang package is automatically imported by Java. 

String name = "Keerthana";

System.out.println(name);

You normally do not need to write: 

import java.lang.String;

java.util Package

The java.util package contains many useful utility and collection classes. 

import java.util.ArrayList;

ArrayList<String> names =
    new ArrayList<>();

names.add("Keerthana");
names.add("Amirtha");

System.out.println(names);

Subpackages

A package can contain subpackages. This allows applications to create a structured hierarchy.

com.jav aLearn/ │ ├── models/ ├── services/ ├── controllers/ └── utilities/

In a real application, each package can contain classes responsible for a particular part of the system.

Packages and Access Control

Packages also work together with Java access modifiers. Members with default access can be accessed by classes in the same package.

Important: Access modifiers such as public, private, protected, and default access determine how classes and members can be used across packages.

Real Project Package Structure

A larger Java application may organize its code like this:

JavaApplication/ │ ├── src/ │ └── com/ │ └── jav alearn/ │ │ │ ├── model/ │ │ ├── Student.java │ │ └── Course.java │ │ │ ├── service/ │ │ └── StudentService.java │ │ │ ├── controller/ │ │ └── StudentController.java │ │ │ └── Main.java
Real-world idea: Models represent data, services contain business logic, controllers handle application flow, and utility packages contain reusable helper code.

Benefits of Packages

  • Better code organization.
  • Reduced naming conflicts.
  • Improved access control.
  • Easier maintenance.
  • Better project structure.
  • Reusable code.

Important Rules

  • The package statement comes before class declarations.
  • Only one package statement is normally used per source file.
  • Package names are commonly written in lowercase.
  • Use import to access classes from other packages.
  • java.lang is automatically imported.
