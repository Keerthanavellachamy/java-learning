What Are Generics?

Generics allow a class, interface, or method to work with different data types while maintaining type safety.

Instead of writing separate classes for String, Integer, Double, etc., one generic class can handle different types.

Why Use Generics?

  • Provides type safety
  • Reduces unnecessary casting
  • Creates reusable code
  • Makes APIs cleaner
  • Catches type errors at compile time

Generic Class

A generic class uses a type parameter such as T. 

class Box<T> {
    private T value;

    void setValue(T value) {
        this.value = value;
    }

    T getValue() {
        return value;
    }
}

Using a Generic Class

Box<String> box = new Box<>();

box.setValue("Java");

System.out.println(box.getValue());
Java

Generic Class with Integer

Box<Integer> box = new Box<>();

box.setValue(100);

System.out.println(box.getValue());
100

Generic Methods

A generic method can accept different data types without creating separate methods. 

class Printer {

    static <T> void
    print(T value) {
        System.out.println(value);
    }
}

Using the Generic Method

Printer.print("Hello");
Printer.print(100);

Generic Method with Two Parameters

static <T>
void display(T a, T b) {

    System.out.println(a);
    System.out.println(b);
}

Generic Interface

interface Container<T> {

    void add(T item);

    T get();
}

Implementing a Generic Interface

class StringContainer
        implements Container<String> {

    private String value;

    public void add(String item) {
        value = item;
    }

    public String get() {
        return value;
    }
}

Bounded Generics

Bounded generics restrict the types that can be used as a type parameter. 

class Calculator<T
        extends Number> {

    private T value;

    Calculator(T value) {
        this.value = value;
    }

    double getDoubleValue() {
        return value.doubleValue();
    }
}

Example

Calculator<Integer>
        c = new Calculator<>(50);

Wildcards

Wildcards represent an unknown type.

  • ? — unknown type
  • ? extends Number — upper bound
  • ? super Integer — lower bound

Unbounded Wildcard

The ? wildcard allows a method to work with a list of any type. 

static void
displayList(List<?> list) {

    for (Object item : list) {
        System.out.println(item);
    }
}

Upper Bounded Wildcard

static double
sum(
    List<? extends Number> list) {

    double total = 0;

    for (Number n : list) {
        total += n.doubleValue();
    }

    return total;
}

Lower Bounded Wildcard

static void
addNumbers(
    List<? super Integer> list) {

    list.add(10);
    list.add(20);
}

Real-World Example: Repository

Generics are useful when building reusable components such as repositories, services, and data containers. 

class Repository<T> {

    private T data;

    void save(T data) {
        this.data = data;
    }

    T find() {
        return data;
    }
}

Using the Repository

Repository<String> names =
        new Repository<>();

names.save("Keerthana");

System.out.println(names.find());
Keerthana

Type Erasure

Java implements generics mainly through a process called type erasure.

  • Generic type information is mostly removed at runtime.
  • List<String> and List<Integer> are both Lists at runtime.
  • You cannot normally create new T().
  • Primitive types cannot be used as generic arguments.
Use wrapper classes such as Integer instead of int.

Important Points

  • Generics improve type safety.
  • Use <T> for a type parameter.
  • Generic classes can work with different types.
  • Methods can also be generic.
  • Wildcards represent unknown types.
  • Bounds restrict allowed types.
  • Generics are widely used in collections.
